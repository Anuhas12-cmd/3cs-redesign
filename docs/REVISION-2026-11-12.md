## Vapor Type access blocker

`npx shadcn@latest add @reactbits-starter/vapor-type-tw --yes` initially reported an unknown registry. The official installation documentation and registry error supplied the correct registry URL and header syntax. `components.json` now references `https://pro.reactbits.dev/api/r/starter/{name}.json` with `Authorization: Bearer ${REACTBITS_LICENSE_KEY}`. No credential is stored in that file.

No license key is present in the project environment or `.env.local`. The official registry returned HTTP 401: **License key required; Starter is a paid tier**. The configured CLI subsequently reported **REACTBITS_LICENSE_KEY missing**. A Starter-or-higher licensed key must be added to local `.env.local`; then rerun the command. Do not use a `NEXT_PUBLIC_` prefix or commit the key. `.env.example` documents the variable.

The central slot is deliberately empty: no different animation has been substituted and actual Vapor Type integration is **not complete**. Once licensed source is available, inspect its installed API before wiring `words={["3CS"]}`, pale text, restrained olive vapor and transparent background. Public API documentation alone does not establish access to the implementation.
